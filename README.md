# CEC Contractors — Website

Static HTML/CSS/JS site for **CEC Contractors**. Editable copy, services list, and portfolio come from **Markdown files** under `content/`, edited with **Netlify CMS** (Decap) at **`/cms/`**. The browser loads those files via **`js/cms-loader.js`**, which reads them from GitHub when you publish changes.

---

## Project layout

| Path | Purpose |
|------|---------|
| `index.html`, `about.html`, `services.html`, `portfolio.html`, `contact.html` | Public pages |
| `css/style.css` | Styles |
| `js/main.js` | Navigation + `window.CEC_PUBLIC` helpers |
| `js/cms-loader.js` | Fetches `content/**/*.md`, parses YAML, applies to the page |
| `js/cms-config.js` | Optional repo overrides (also generated by `scripts/build-config.js`) |
| `js/js-yaml.min.js` | YAML parser for front matter |
| `content/pages/*.md` | Site text rows (`page \| section \| content_key`) |
| `content/services/*.md` | Service items |
| `content/portfolio/*.md` | Portfolio items |
| `cms/index.html` + `cms/config.yml` | Netlify CMS UI |
| `images/uploads/` | Media folder for CMS uploads |

## Editing content

1. Deploy the repo to **Netlify** (or run locally with the CMS dev server — see Netlify CMS docs).
2. Enable **Git Gateway** + **Netlify Identity** so `/cms/` can commit to GitHub.
3. Open **`/cms/`**, sign in, and edit **Pages**, **Services**, or **Portfolio**.
4. Publish; after the build deploys, the public site reads the updated Markdown from the repo.

Legacy **`dashboard.html`** is a UI shell only; real editing is through **Netlify CMS** at **`/cms/`**.

## GitHub loader (public site)

Each HTML page includes:

```html
<meta name="cec:github-repo" content="YOUR_GITHUB_USERNAME/cec-contractors" />
<meta name="cec:github-branch" content="main" />
```

Replace `YOUR_GITHUB_USERNAME/cec-contractors` with your real **`owner/repo`**. The loader:

1. Calls the **GitHub Git Trees API** for that branch (optional `CEC_CMS_CONFIG.token` for higher rate limits or private repos).
2. Downloads each `content/**/*.md` file from **`raw.githubusercontent.com`**.
3. Parses front matter with **js-yaml**, maps portfolio `image` → `image_url`, sorts by `order_index`, then calls `window.CEC_PUBLIC.applySiteContent`, `renderServices`, and `renderPortfolio`.

If the tree API fails, a built-in path list is used. If **no** repo is configured and the site is **deployed**, the loader falls back to same-origin **`fetch('/content/...')`**.

## Netlify build (optional)

Set **`CEC_GITHUB_REPO`** to `owner/repo` and run before deploy:

```bash
node scripts/build-config.js
```

This overwrites **`js/cms-config.js`** so you can omit meta tags if you prefer (meta still works as a fallback).

---

## Contact form

The contact form targets **Formspree**. Replace **`YOURFORMID`** in `contact.html` with your form endpoint.

---

## Local preview (no GitHub metadata)

Opening files with `file://` will block `fetch`. Use a static server from the repo root (for example `npx serve .`) so `/content/...` can load. Configure the meta tag with your GitHub repo to test the API path against the live remote.

---

## License / keys

Do not commit secrets. The public site only needs a **public** GitHub repo (or anonymous read access to `raw.githubusercontent.com`). Optional PAT for **`CEC_CMS_CONFIG`** belongs in tooling only — avoid exposing tokens in client-side scripts checked into Git.
